# MathorCup 工作台

个人竞赛任务管理工具，使用静态 HTML、CSS 和 JavaScript，无第三方运行时依赖。支持任务依赖、交付物登记、AI 执行指令整理、最终自检及 JSON 备份。

## 使用

先安装 Node.js。Windows 用户双击 `start-workbench.cmd`，会启动本地服务并打开浏览器；也可以在项目根目录运行：

```bash
node start-workbench.cjs
```

浏览器打开 <http://127.0.0.1:8765>。关闭服务窗口或按 Ctrl+C 停止服务。再次使用时运行同一启动命令。

## 工作流程

1. 查看当前可开始的任务，确认目标、前置依赖和预期交付。
2. 根据需要复制 AI 辅助指令，并在实际执行环境提供题目和文件。
3. 登记真实的交付物路径、关键结论和交接说明，再标记任务完成。
4. 全部任务完成后核对最终自检，导出项目备份。

工具负责管理任务和记录，不会自动调用 AI 或读取登记的文件。实际竞赛工作须遵守当届规则；AI 使用情况应据实记录，采用内容由参赛队员核验。

## 数据保存与备份

进度保存在当前浏览器的 `localStorage` 中。GitHub 仓库保存程序源码，不会自动同步浏览器进度。

- 定期在「数据与备份」中导出 JSON。
- 更换设备、浏览器或访问地址时，在新页面中导入原备份。
- 导入会替换当前进度，操作前保留需要的备份。
- 使用同一浏览器和固定地址 `http://127.0.0.1:8765`，可继续访问本地进度。

## 验证

在 `workbench` 目录执行原有 16 项测试：

```bash
node --test test.cjs
```

也可在项目根目录运行 `npm test`。测试包含任务依赖、交付校验、返工、最终自检、备份和界面事件模拟，不代替真实浏览器视觉检查。

## 目录

```text
workbench/dist/       静态页面、样式和业务逻辑
workbench/test.cjs    原有自动化测试
start-workbench.cjs   本地 HTTP 服务，仅监听 127.0.0.1:8765
start-workbench.cmd   Windows 双击启动入口
package.json         启动与测试命令，无安装依赖
```
